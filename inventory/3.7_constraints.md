### Observaciones clave

1. **Dominios personalizados implementados:**
   - `global.email_address`: Validación de email
   - `global.phone_number`: Validación de teléfono
   - `global.currency_code`: Códigos de moneda ISO
   - `global.timezone_name`: Zonas horarias válidas
   - `ticketing.event_status`: Estados de evento
   - `ticketing.ticket_status`: Estados de ticket
   - `billing.payment_status`: Estados de pago

2. **CHECK constraints importantes:**
   - `ticketing.events`: `ends_at > starts_at`
   - `ticketing.ticket_types`: `sold_quantity + reserved_quantity <= total_quantity`
   - `billing.orders`: `total_amount = subtotal + tax_amount + service_fee_amount - discount_amount`
   - `ticketing.tickets`: `status` en lista de valores permitidos

3. **Columnas generadas:**
   - `ticketing.ticket_types.available_quantity`: `total_quantity - sold_quantity - reserved_quantity`
   - `ticketing.ticket_types.is_sold_out`: `available_quantity <= 0`

4. **UUID público:**
   - Todas las tablas principales tienen `public_uuid` con `gen_random_uuid()` como default
